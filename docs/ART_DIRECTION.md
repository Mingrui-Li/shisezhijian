# 《拾色之间》美术与界面规范

日期：2026-10-27。当前唯一视觉规范。对应 [点击填空玩法](GAME_DESIGN.md)，参数源为 `assets/design/design-tokens.json`。

## 1. 轻松、温馨、像一个小游戏

界面以奶油白、浅杏、清透薄荷和少量明亮彩色表达温暖。使用圆润的胶囊按钮、轻量面板、宽松留白和很短的弹性反馈。彩块本身承担视觉主角，装饰只在非解题区域出现。

中文采用清晰的圆润无衬线字体，正文与数字都避免宋体衬线、书法笔画和过大字距。优先使用系统可用的无衬线字体；需要专用圆体时先确认授权与中文包体成本。模型参考图中的文字仅是意图，生产文字由游戏 Label 渲染。

主标题简短友好，游戏页不重复巨大“第 XX 关”标题。用小章名、关卡号和关名提供位置感，步数放入轻巧胶囊。少用硬边细描线大框、浓重阴影、大面积深绿或灰黑遮罩。弹窗通过柔和浅色面板和局部暗化建立层次，不让失败画面压迫。

## 2. 游戏页必须看出填空

竖屏自上而下：安全区与返回 → 关号/名称/剩余步数 → **带空槽的完整轨道** → 简短选色提示/取回操作 → **固定候选槽与分页** → 撤销及道具。

开局只能在上方显示固定提示色块，其余是空槽；下方必须明显摆出待选颜色。不能用摆满彩块的盘面表达正常开局，也不能在后章隐藏候选区。

轨道的实际几何来自关卡路径。网格中的留白属于题目形状，不自动补成整张矩形。浅中性连接线在色块后面，只表现真实路径；共享交点只画一次。空槽用轻灰浅底与柔和边界，能清楚与“这里没有轨道”区分。

### 点击与选中反馈

先点候选，块外出现有间距的清楚轮廓；再点上方空槽，颜色以短位移动画落定。选中轮廓不叠进色面、不改变透明度；可配一枚块外小标记，不能只靠颜色表示选中。

点击已填色块选中后，可点另一空槽改放，或点“放回待选区”。被占用槽与提示块不会亮成可放目标，点击时用轻提示说明，不进行两块互换。候选分页不取消选择；取消选中不消耗步数。

不在正确块上出现自动星标、绿框或锁；不显示逐块对错和百分比。原始提示块与点睛辅助锁采用不同的块外形状，长按不承担主交互。

### 大关布局

最大题目为 6×6 逻辑范围、36 个真实格位；最多 32 枚候选。上方轨道与当前候选页必须同屏。候选标准每页最多18槽（6列×3行），第二页显示第19–32枚；安全区较大或短屏可降为12或6槽，页码按实际页数显示。分页左右按钮与页码清楚可触达；槽位固定，不因空缺重排。

以 390×844 为参考画布，按设备安全区实际布局。在较窄屏保持色块可比较、目标可点击，优先压缩无意义标题与留白。普通按钮有效触达至少约 44–48 逻辑单位；密集色块的尺寸、间隔和触达需以真机误触情况验收。不能靠压成小点或让整页滚动容纳大关。

## 3. 解题色块的硬边界

- 盘面、候选、参考层与收藏都读取同一份关卡纯 `#RRGGBB`，完全不透明。
- 色面不加渐变、纹理、发光、玻璃反射、内高光、环境色、滤镜或会改变辨色的阴影。
- 圆角可以柔和，但颜色可比较的中心面积须足够大。装饰性 2.5D 彩块只能用于图标和首页。
- 选中、提示、辅助锁、低步数与不可操作状态都通过块外标记或周围 UI 表达，不染色答案。
- 不从 Image 图吸取关卡 HEX，不用模型画出的棋盘替代真实数据。

丰富自然配色已经确定，UI 底色保持中性，不能把整关置于强烈有色背景。详见 [自然配色规范](COLOR_SYSTEM.md)。

## 4. 公共组件

首轮固定胶囊主按钮、轻次按钮、圆图标按钮、步数胶囊、纯色色块、空槽、候选槽、外部选择轮廓、原始提示/辅助锁标记、候选分页、道具按钮、Toast 和底部面板。全项目从 tokens 读取颜色、字体、圆角、间距与动效。

主游戏页道具按“点睛、窥色、续步”固定排列，用简洁图形和库存徽标表达；完整效果与使用次数放到详情面板。库存为零、次数耗尽、失败不可用和广告请求中各自写明原因，不能全部模糊成一种灰态。撤销首次提示不返步数。

按钮文字不使用散乱空格或沉重长句。可用：“继续拾色”“放回待选区”“看视频 +X 步”“免费重新挑战”。数字和奖励实时读取状态，不写死示意图里的例值。

## 5. 页面与反馈

加载页可有轻柔彩色形状和真实加载进度；进度失败提供重试。首页突出一枚“继续拾色”，章选、色谱收藏和设置为轻入口，不做信息密集大厅。关选用五章各二十关，完成、进行中与锁定状态用形状和文字共同区分。

通关使用短暂的色路收束、轻音效与自然配色名，然后进入下一关。主线不加入长庆祝动画或持续粒子。一次落色给短促柔和反馈；错点不使用刺耳警报；道具效果可被看懂但不拖慢下一个操作。

失败面板标题“就差一点点”，正文明确“步数用完了，颜色还为你留着”。清楚展示视频标识、“看视频 +X 步”、本局剩余复活次数、免费重开与返回。画面保留已整理颜色，不泄露正确率，不用温和文案掩盖失败。关闭面板后普通解题操作仍暂停。

视频不可用时说明原因，免费路径保持可用。视频补货写“看视频领取 1 个”，先发库存再由玩家使用，不能将视频入口包装成无条件免费。两类视频额度按真实状态展示。

## 6. Image 的使用与生产边界

点击填空视觉参考已保存为 `assets/design/shisezhijian-tap-fill-ui-v1.png`，由内置imagegen生成；提示词为 `assets/design/prompts/tap-fill-ui-v1.txt`。它确认上方空槽、下方候选和轻暖风格，不是某一关的准确答案或运行截图；图中面色/阴影不能替代程序纯HEX规范。

Image 用于探索整体风格、加载/首页装饰、图标或独立位图。生成时明确上方提示块与空槽、下方候选、点击操作、无衬线中文和轻暖氛围。公共组件通过程序还原，不能把一张整页参考图铺上去充当可交互页面。

定稿后固定 tokens、独立素材与清单。后续页面沿用同一基准，不重新产生互相矛盾的按钮、字体或道具命名。源提示词、原始输出与采用状态放在资源清单；只将确认的运行时素材打包，设计板和审阅图留在工程外。

## 7. 验收画面

至少复核：第一关开局、16 格普通关、36格/32候选的多页、选中池色块、选中已填块、取回、低步数、失败、道具无库存、视频不可用、关闭动效和后台恢复。

分别记录模型参考图、实际客户端截图、抖音真机操作，三者承担不同证据。尤其确认字体没有衬线替换、候选槽不跳位、页码可点、上轨道不被面板挤出、提示和选择不污染色面。真实手机上复核比较颜色与点选的舒适度。
