# 加载页信息标识与适龄说明

核对日期：2026-10-27。以下是开发测试版实现记录，不能作为“已经通过平台审核”或“已经完成防沉迷接入”的声明。

## 本轮实现

加载页使用独立插画 Sprite 与原生 Cocos 文字、进度条叠加。进度只能由资源加载回调更新，不以计时器伪造。底部保留可读的《健康游戏忠告》，适配安全区；文本不会交给图像模型生成，以免错字或缩放导致不可读。

健康游戏忠告全文固定为：

> 抵制不良游戏，拒绝盗版游戏。注意自我保护，谨防受骗上当。适度游戏益脑，沉迷游戏伤身。合理安排时间，享受健康生活。

测试版显示“适龄说明 · 开发测试版”，点击后打开原生说明弹层。开发包尚未获得适龄信息确认，因此不自行绘制 8+、12+ 或 16+ 标识，不声称通过任何评级。正式适龄标识及说明应与抖音后台一致。

默认弹层准确介绍点击渐变拼图、步数挑战和自愿观看广告的道具功能，并提示“正式适龄提示以抖音平台审核后展示为准”。这是开发状态说明，不替代平台适龄说明。

## 官方依据

1. [抖音小游戏内容规范，第 11 节](https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/content-norms-for-mini-game)：开始前显著显示完整健康忠告；同时要求相应信息标识与未成年人保护措施。
2. [小游戏备案审核规范](https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/game-record-spec)：平台已配置健康忠告；开发者画面若出现相关内容，应完整准确。若截图出现适龄图标，须用标准格式，不能自创或更改。
3. [小游戏审核常见问题：适龄篇](https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/guide/contactus/age)：适龄提示分 8+、12+、16+；根据实际内容、类型和功能评估；平台加载页显示对应图标，点击查看说明；开发者在基础设置编辑说明文案。
4. [小游戏适龄提示分段表](https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/right-age)：按实际游戏情况提交适龄年龄段和说明。

根据现有轻松卡通表现、单人点击拼图、无自由社交等特点，可以先按 8+ 方向做内容自评；这是开发建议。后期高难度关卡、广告功能及运营方案也须纳入评估，不据此直接宣布正式年龄段。

## 上线前需要落实

- 在抖音后台核对并提交实际适龄年龄段与说明，按后台模板逐项填写，确认平台加载页适龄图标和弹层在真机显示正常。
- 将开发期入口状态改为与后台相符的正式信息，避免展示开发占位说明或自创适龄标识。
- 核对出版、著作权、备案及平台对该游戏主体实际要求的信息和资质；以取得的真实信息显示，不编造批准文号、出版号、登记号。
- 核对实名认证、防沉迷与未成年人保护能力的实际接入和真机行为；健康忠告文字本身不等同于已完成这些能力。
- 验证刘海、胶囊和底部安全区；常见竖屏宽度 390 设计单位下忠告正文为 12，完整四行显示，不隐藏在进度条或按钮后。
- 正式发行时重新核对平台最新审核规范。本文件只记录核对日可访问的官方要求。

## 集成接口

`new LoadingScreen({ parent, width, height, safeTop, safeBottom, artwork?, onAgeInfo? })`

- `setArtwork(frame)`：按原图比例 cover 画面，正文和进度条仍由 Cocos 渲染。
- `setProgress(ratio, status?)`：比例 0–1，单调增加；由真实资源加载数量或明确的初始化阶段更新。
- `openAgeInfo()` / `closeAgeInfo()`：默认开发期适龄说明弹层。可以传 `onAgeInfo` 接入项目统一弹层。
- `destroy()`：移除整页节点。资源就绪后进入首页，不自动进入第一关。

调用方决定加载完成后的切换时机；不要用一闪而过的文字代替可读声明。
