# 点击填空核心规则与测试记录

日期：2026-10-27。当前规则标识：`click-fill-v1`。当前题库：`data/levels/levels.v0.4.json`，schema `3.0.0`，content `0.4.0-candidate`。

## 核心接口

`game/assets/scripts/core/index.ts` 是不依赖 Cocos 或抖音 SDK 的纯 TypeScript 规则模块。选择候选色块、取消选择、切换选择和点击反馈由 UI 层处理，核心只接收已经确认的动作，存档不记录未提交选择。

| 动作 | 参数 | 结果与消耗 |
| --- | --- | --- |
| `place` | `poolIndex, toCellId` | 候选区色块填入空格，消耗 1 步，原候选槽保留空位 |
| `move` | `fromCellId, toCellId` | 已放色块移入另一空格，消耗 1 步，原轨道格留空 |
| `returnToTray` | `fromCellId` | 色块回到自身永久候选槽，免费，已经消耗的步数不返还 |
| `undo` | 无 | 恢复最近一次盘面、候选槽和辅助锁，不返还步数、道具或广告次数 |
| `locate` | 无 | 自动归位一个未正确目标并辅助锁定，不耗步；目标原错块回自身候选槽 |
| `peek` | `pathId, nowMs` | 仅显示选中色路的正确颜色 3 秒；期间冻结操作，不改真实盘面 |
| `addMoves` | 无 | Playing 状态增加 5 步，消耗续步道具 |

占用格不能被直接覆盖，原始锚点和辅助锁不可移动，无效操作不耗步。判断通关必须同时满足轨道已填满、每格目标 HEX 正确、候选区全部为空；最后一步先判断通关，再判断步数耗尽。

前 4 关不限步，第 5 关起采用有限预算。失败后冻结填入、移动、免费取回、撤销和道具，只允许复活、免费重开或返回。视频奖励通过独立平台层确认后再提交，核心不会把“发起视频”当成“完成观看”。

## 存档边界

`restoreAttempt(level, input)` 与 `restoreGame(level, input)` 严格检查规则版本、题库版本、色块守恒、固定候选槽、锚点、辅助锁、步数账目、局面状态、撤销历史及奖励请求。旧玩法尝试会被拒绝，不能拿旧盘面直接套入新规则。应用层可分别保留历史完成进度、合法库存和已领取标记，丢弃不兼容盘面，防止重复发放赠礼。

广告账本按 request ID 幂等结算；取消、失败和未确认观看均不发奖、不占成功奖励次数。跨重开或换关的晚到复活回调形成待用权益，不能改变新盘面；晚到补货只增加库存。原局面、候选槽、辅助锁及撤销记录在本局有效复活后保留。
