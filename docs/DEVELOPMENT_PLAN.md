# 《拾色之间》开发计划

日期：2026-10-27。执行依据：[游戏设计](GAME_DESIGN.md)。所有客户端、题库和验收均使用“选色后点空槽”的点击填空规则。

## 1. 技术路线

正式客户端采用 **Cocos Creator 3.8.8 + TypeScript**，输出竖屏抖音小游戏。固定补丁版本；更新引擎先在独立任务验证，不在开发中自动升级。Cocos 的抖音构建流程为正式目标，网页预览只是反馈渠道，不能将 HTML 图鉴或 H5 页面当成发布客户端。

采用一个稳定启动场景，公共组件由参数化代码组成。规则和题库不依赖引擎；渲染层只解释状态，不自行推导另一份答案。已有实现必须重新按点击填空验收，历史测试数量不作为本规则的完成证据。

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| core | 色块位置、填入/取回/改放、守恒、撤销、判胜、限步与道具 | 纯 TypeScript，不导入 `cc`、`tt` 或广告 SDK |
| content | 导入并验证唯一题库 `levels.v0.4.json` | 运行时不临时换色或修补错误题目 |
| application | 尝试、页面、进度、库存、奖励账本与存档协调 | 原子动作与展示动画分开 |
| render / ui | 轨道、界面选中状态、候选分页、选择轮廓、公共组件与页面 | 不给正确块额外标记，不修改目标 HEX |
| platform | 安全区、存储、前后台、音频、触觉与广告 | 显式区分开发模拟与真实抖音能力 |

主要目录为 `game/assets/scripts/` 下对应模块；源题库在 `data/levels/`，美术输入在 `assets/design/`，生成物进入游戏工程内 `resources/generated/`。生成物不手改；构建先生成和校验，再同步资源，失败立即停止。

## 2. 数据接入契约

所有关卡均只预填原始提示块，其余色块进入乱序候选池。候选原槽固定、不可重排。上方每格与每枚色块具有稳定 ID；路径引用共用交点；选中状态不是一个新位置。

每关提供格位、路径、提示块、目标 HEX、开局、候选槽、内容版本、预算与可执行证解。证解为候选到目标的一次填入，不使用另一种移动模型证明可解。最少有效动作等于初始空槽数 `N`。题库导入时检查：

- 五章百关、ID/坐标合法唯一、路径连续、共享格一致。
- 只预填提示块，候选池恰好容纳其余每块，数量与空槽相等。
- 所有色块在盘面或候选原槽中恰好出现一次，选中不复制色块。
- 证解逐步执行可完成，预算不少于证解动作，前四关预算为空。
- 自然 HEX、轨道和提示块符合已接受内容；色域、邻关变化和色差诊断可复现。

当前题库是可执行候选，不自动升级为真人或真机已验收。修改答案、轨道、提示块、开局或预算需增加内容版本。存档保留题库版本与单关版本；不在玩家进行中悄悄替换。

## 3. 关键状态与事务

主状态：`Playing / PreviewingReference / AdPending / Won / Failed`。短暂的动作解析和发奖由应用层锁定输入。失败态禁止解题动作、撤销和道具；仍能查看候选页、请求允许的复活、重开和返回。

尝试至少保存 `attemptId`、关卡版本、revision、盘面、固定候选槽、辅助锁、撤销栈、初始/剩余/已花步数、道具已用次数、两类广告计数与请求上下文。全局另存库存、通关进度、一次性礼物、设置和已发奖账本。

有效动作先原子提交盘面与计步，先判胜、再判步数用尽。选择和取消不写盘面撤销历史。取回免费但此前花费不退；撤销恢复盘面与辅助锁，不返还步数、库存和权益。填入、改放、取回、点睛和撤销必须保持色块守恒。

点睛有占位时将占位块送回自己的候选原槽，再归位与辅助锁定目标块；整个过程在一次事务内，不能产生半次归位。窥色使用独立参考层，关闭与切后台不写答案；续步只增加剩余步数。

广告请求唯一 ID 在发起前落盘，确认完整观看后的奖励与去重记录一起提交。取消、错误、重复与迟到回调分别覆盖；发奖不直接写已销毁页面。平台接口只报告观看结果，奖励量与上限由应用规则计算。

## 4. 按门槛推进

| 阶段 | 可检查产物 | 通过门槛 |
| --- | --- | --- |
| A 纠偏基线 | 唯一现行规格、点击核心、百关填空开局、预算与证解、上轨道下候选示意 | 无有效路径残留错误规则；全量数据与核心测试通过 |
| B 首关闭环 | 固定提示块、点选填入、免费取回、改放、取消、完整判胜 | 实际操作只能点空槽放入；占用格不覆盖；固定候选槽守恒 |
| C 挑战闭环 | 一关限步题、三个道具、失败、免费重开与模拟视频复活 | 最后一步先判胜；失败冻结；撤销不返资源；奖励幂等 |
| D 十二关与大题压力 | 前 12 关、进度/库存恢复、L072/L078/L100、多页候选 | 窄屏上轨道与当前候选同屏；32 候选可查看；后台恢复没有丢块 |
| E 页面与全百关 | 统一轻暖组件、加载/首页/章选/通关/设置；五章逐批接入 | 每关可载入、可证解回放；逐章真人审查记录明确，完整页面可交互 |
| F 抖音与发布候选 | 正式平台构建、真实存储与生命周期、真机记录、真实广告 | 开发者工具载入与 Android/iOS 真机分别通过；广告失败不损害进度 |

视觉概念和公共组件可与规则纠偏并行，但扩展全部页面要在首关闭环成立后。先校验最大 36 格轨道与 32 候选，再批量制作页面，避免晚期发现玩法放不进竖屏。

不承诺固定几天生成一个“可上线百关游戏”。源码完成、测试通过、引擎构建成功、开发者工具载入、真机操作与真人试玩是不同证据，逐项记录。

## 5. 公共 UI 的实施

视觉以 [美术规范](ART_DIRECTION.md) 和 `assets/design/design-tokens.json` 为准。Image 用于风格参考、加载/首页装饰和位图素材；按钮、文字、步骤数字、解题色块与状态由程序实现。模型示意图不作为游戏整页贴图。

首先实现：胶囊按钮、图标按钮、步数胶囊、固定提示标记、外置选中轮廓、空槽、候选槽、候选分页、道具按钮、底部面板和 Toast。完整实现默认、按下、选中、不可用、忙碌状态，再组合页面。

所有解题色块从 JSON 的 `#RRGGBB` 直接绘制、完全不透明、无灯光或色调后处理。池与盘面使用同一颜色转换。选择、原始提示与辅助锁通过块外形状表示。程序界面使用清晰的无衬线中文，不使用图片中文字代替动态文本。

页面输入仅用点击。滚动和长按不承担填色、改放或取回；候选换页使用按钮。触摸取消、双击、同时多指和动画期间的连点要避免重复提交。平台胶囊、安全区和底部手势区域进入布局。

## 6. 存档与恢复

存档区分应用版本、存档结构版本、内容包版本和单关内容版本。有效操作、道具、发奖、失败、通关、换关和切后台触发保存；短时间写入可合并，但关键生命周期节点主动提交。

使用带 revision 的主副快照。写入新快照并验证可读后更新索引；读失败回退上一份。恢复时校验色块守恒、提示块、候选原槽、锁与步数。坏单关不连带清空全部进度，未经验证的撤销记录可舍弃。

旧规则的进行中盘面不迁移为新的可操作盘面：保留合法的通关与库存权益，按当前题库安全重建该关尝试并说明更新。不能保留一份没有候选池的盘面继续游戏。首发本地存档不承诺跨设备同步。

## 7. 必须通过的检查

自动测试集中于状态和资源风险，不为每个圆角或文案编写重复实现的测试：

- 点击选择、候选填入、已填块改放、原槽取回、取消与无效占位；提示块不可动，辅助锁正确。
- 最大候选分页、选中跨页与取回原槽；连续动作中没有丢块、复制或重排。
- 最后一步成功、零步失败冻结、无限步教程、免费重开与撤销不退资源。
- 点睛占位清理及整事务撤销，窥色关闭/后台恢复，续步使用状态及次数。
- 存档往返、损坏回退、内容版本变化、礼包不重复发放。
- 广告成功、取消、加载失败、重复/迟到回调、两类计数隔离与一次性发奖。
- 100 关开局守恒、预算与证解逐步回放；失败数据拒绝，不打包带错数据。

人工与真机检查覆盖窄屏、常见长屏、最长关名、库存零、低步数、失败、视频不可用、减少动效、后台恢复和声音中断。至少记录一台 Android 与一台 iPhone 的设备、系统、宿主版本、基础库与包版本。

构建验证使用本机固定编辑器与实际导出的平台配置，不猜测 CLI 参数。包体、启动时间、点击到反馈、帧时间、内存和恢复表现必须测量后记录，不能依据小样结构宣称秒开或固定帧率。

官方实施入口：[Cocos 3.8 抖音发布](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-bytedance-mini-game.html)、[Cocos 命令行构建](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-in-command-line.html)。平台规则与发布要求在实际接入和提审时重新核对。

## 8. Codex 协作方式

一次任务交付一段可检验闭环，明确读取规格、文件所有权、接口、运行检查与输出证据。规则、内容、UI 与集成可并行，不同时修改同一启动场景、类型契约或生成文件。接口变化先同步消费者。

每次合入记录实际改动、真正执行的命令、输出结果与尚缺的证据。独立模块可继续推进；无法运行真机或广告时明确未验证，不能用源码检查替代。当前进度只维护在 [开发状态](DEVELOPMENT_STATUS.md)，不创建多份并列的开工与版本规划。
