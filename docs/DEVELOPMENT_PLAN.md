# 《拾色之间》开发计划

日期：2026-10-28。当前1.1.0已完成自动回归、双目标构建、Web验证及抖音工具首页/官方预览取证；手机和真实广告另行验收。唯一实施依据为[当前游戏设计](GAME_DESIGN.md)：点击补色、全关倒计时、积分购买道具、自愿激励视频。

## 1. 技术与职责

正式客户端使用 **Cocos Creator 3.8.8 + TypeScript**，输出竖屏抖音小游戏；网页构建用于实际客户端反馈。固定引擎补丁版本，规则、题库和持久化逻辑独立于引擎渲染。一个Boot场景承载页面，由当前状态驱动原生组件，不制作第二套H5玩法。

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| core | 盘面守恒、填入/改放/归还/撤销、判胜、计时、积分、道具、奖励事务 | 纯TypeScript，不导入cc/tt/SDK |
| content | 导入唯一运行题库 `data/levels/levels.v0.6.json` | 不临时换色、改答案或对玩家动态加难 |
| application | 页面、尝试、进度、赠礼、购买与存档协调 | 解题状态与演示动画分开 |
| render/ui | 统一解题面板、首页、动图教程、道具屋及反馈 | 只解释状态，不推导另一份答案 |
| platform | 安全区、存储、前后台、声音、触觉、真实广告 | 未配置能力明确不可用，不冒充真实奖励 |

源文件位于 `game/assets/scripts/`；美术源和提示词在 `assets/design/`，运行资源在 `game/assets/resources/`。唯一题库为schema4.1.0、contentVersion0.6.0的点击填空数据，生成后同步运行资源；生成物不手改。

## 2. 题库与计时契约

第13–100关保留已确认的目标HEX、几何、路径、交点和提示块；前12关在独立作者改版源下扩大结构并按原自然主题重新采样，不覆盖已认可原始基线。每关只预填提示块，其余色块经过受约束洗牌进入固定位置候选槽。色块可收回任意空候选槽，不与某个槽永久绑定；初始索引元数据只供证解和seed复现。每关提供目标、开局、路径、候选、版本、时间参数和逐块填入证解。

```text
L001：45秒
其余：clamp(45 + N × k, 45, 240) 秒
N为初始空槽数；k依次为第一/二章6、第三/四章5、第五章4
复活：+30秒，每次尝试最多2次
```

数据验证检查百关数量、ID和坐标唯一、路径连续、交点一致、候选守恒、提示块锁定、目标自然色值、时间范围及公式、证解可执行。全库至少4候选；洗牌禁止目标正序/倒序，错位比例至少75%，最长正反连续段至多2，相邻目标对比例不超过35%，4096次内无法满足则生成失败。验证器重算质量并拒绝伪造记录。解题动作数只用于评分，无次数耗尽失败。题库不保留另一套限次预算字段。

修改时间、开局或答案时同步内容版本、运行资源和验证报告。自动回放证明逻辑可解；真人难度、颜色感知和时间压力仍须试玩校准。

## 3. 状态与事务

主状态为 `Playing / PreviewingReference / AdPending / Won / Failed`。可解题状态按正数毫秒推进剩余时间，归零触发失败；输入在提交前先核对计时状态。已经提交的通关不受后续计时回调影响。失败冻结盘面、归还、撤销和道具，分页可查看。重开创建新attemptId，保留全局库存、积分和一次性权益。

尝试保存attemptId、版本、revision、盘面、候选槽当前实际占位、辅助锁、撤销栈、初始/剩余/累计时间、有效动作数、道具次数、复活/补货次数及广告上下文。全局钱包保存积分、每关最佳成绩、每关双倍领取标记、库存、奖励账本和待用复活权益。

每个盘面动作原子提交且保持色块守恒。撤销只恢复盘面和辅助锁，不退时间、有效动作、库存、本道具限额或广告额度。点睛先提取正确块腾空，再将错误占位块收回任意可用候选空槽，最后归位锁定，一次原子完成；窥色仅参考层3秒，关闭或后台不写答案；续时只对进行中增加30秒。

计时明确区分游戏进行、菜单/教程、参考、视频等待和后台。暂停状态不接受解题输入；恢复不重置时间。冷恢复与旧内容升级重建不兼容尝试，保留通过验证的合法全局权益。

## 4. 积分与商店

成绩按核心函数计算100–200分：100基础、最高50效率分、最高50时间分，每次本道具使用及复活扣10分，最低100。首次入账完整成绩；回玩只发历史最佳提高的差额，持平和下降不入账。前12关采用独立成绩代次expanded-0.6，保留旧钱包而不以旧简单题成绩阻挡新版奖励；同代次重复挑战继续防刷。额外时间不能提高成绩上限。

| 道具 | 价格 | 使用效果 | 本局限额 |
| --- | ---: | --- | ---: |
| 点睛 | 120积分 | 归位且辅助锁1块 | 2 |
| 窥色 | 80积分 | 一路参考3秒 | 1 |
| 续时 | 100积分 | +30秒 | 2 |

初始各1；L004首通额外3/2/1；每章首次全通各1。赠礼有独立去重标记。首页道具屋显示余额、库存、价格与效果；道具详情展示本局额度，可跳转购买。扣积分和加库存为同一持久化事务，保存失败回滚；购买不自动使用，不能重置本局限额。

## 5. 广告接入

真实奖励均走同一个幂等奖励账本：失败续玩+30秒（每局2次）、结算双倍本次积分入账（每关1次）、缺货领取指定道具1个（每局1次）。请求先持久化ID、尝试/关卡上下文和奖励金额，等待时锁重复请求；只有平台完整观看结果发奖。取消、失败、未知和重复回调不多发奖励。

迟到复活不改新盘面，保存为一次性待用权益；迟到双倍按请求中冻结金额只入账一次。奖励与成功额度、领取标记一起提交，不能只保存其中一半。真实存储失败需可见且不吞权益。

用户尚未开通广告位，保留真实SDK适配器与三个业务入口，显示“广告暂未开放”；不在正式界面提供模拟领奖。取得adUnitId后验证SDK加载、展示、完整观看、取消、失败和重复回调。真实广告收入与填充率以抖音后台为准。

## 6. 页面与动效

加载使用现有Image自然彩带插画、真实资源进度、完整健康忠告和用户确认的可点击8+标志。首页始终是首屏目的地，花园主体和标题副标题分开排布；入口为关卡、教程、道具与设置。关选全部显示数字关号，锁定与完成以附加标记表达。

教程三页为5–6秒原生tween循环：点选填空、改放归还、三个道具。演示使用独立局部节点，不改变真实库存或存档；翻页没有练习完成门槛，离开停止所有tween。减少动效时阶段切换代替连续位移。

轨道和候选放在同一轻面板，短题间距44、大盘32，整组居中；分页跟随候选。底部保留动作和道具入口。纯色色块直接读取JSON的HEX，不叠高光或滤镜；图像模型只产插画和装饰图标。全部动态文字由清晰无衬线Label显示。新增专用WinPanel与透明庆祝插画：超大得分、到账条、两列统计、金黄视频双倍次按钮、珊瑚下一关主按钮、首页轻链接；短屏布局单独验收。

## 7. 需要通过的检查

自动检查集中于真正的状态、财产和资源风险：

- 点击填入、改放、指定任意空候选槽收回、自动收回、无效占位、固定块与辅助锁、跨页选择，以及连续操作色块守恒。
- 计时边界、归零失败冻结、先通关后计时事件、重开初始时间、暂停和恢复。
- 评分上下限、有效动作与辅助扣分、最佳差额防刷、双倍每关只领一次。
- 道具限额、点睛占位清理与撤销、窥色关闭、续时进行中限定。
- 初始库存、L004与章节赠礼去重、积分购买扣加原子性、保存失败回滚。
- 广告成功/取消/加载失败/未知/重复/迟到回调、不同业务额度隔离、待用权益持久化。
- 存档往返、主副快照回退、版本迁移、前12成绩代次，以及百关开局、洗牌质量、时间配置与证解。
- 390×694及长屏的6×6/32候选可达性、至少44触达、两个解题区域间距和分页避让。

人工检查覆盖首页净空、8+说明、关号可读、三页动画、首关到结算积分到购买、时间紧张、超时失败、道具缺货与无广告位。前12结构与大盘点睛要覆盖非原槽收回后的连续操作及保存恢复；专用胜利卡需实际查看插画、分数和按钮层级。实际运行截图与静态几何测试分开记录，至少补齐Android和iPhone的宿主、系统、基础库、包版本和前后台结果。

## 8. 构建、导入与交付

使用固定Cocos官方CLI生成真实web-mobile和bytedance-mini-game包，检查成功码、完整引擎适配器、AppID、场景、运行题库一致及文件哈希。构建成功不等同模拟器和真机运行通过。

Cocos工作输出与最终抖音导入目录分开，构建中不清空已导入包。核验后只保留当前交付的一个抖音导入目录，历史导入副本删除，避免用户误开旧包。运行日志和必要验收证据留在artifacts，不把重复发布包作为备份。

实际包体、启动时间、输入反馈、内存与前后台恢复须测量；不按代码结构宣称秒开或固定帧率。当前运行证据只维护在[开发状态](DEVELOPMENT_STATUS.md)和对应UI/平台报告，不能用上一版检查结果为本版签收。
